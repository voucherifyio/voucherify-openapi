Workflows connect Loyalty v2 events to external applications. A trigger starts a run when an event matches. An IF operator can send that run down a **True** or **False** path. A webhook callout on the path that was taken sends the event to your endpoint.

## When to use Workflows

Use Workflows when an external application needs to react to Loyalty v2 events. For example, you can send loyalty events to:

- A customer relationship management (CRM) platform.
- An email or customer engagement platform.
- A custom application.

Connect a trigger directly to a webhook callout when every matching event should be sent. Add an IF operator when only some of those events should leave Voucherify. For example, notify your CRM when a member earns more than a set number of points, and send nothing for smaller earnings.

## Who can use Workflows

**Admin** and **User** can create, publish, and activate workflows. **Viewer** can open them only. **Merchant** and **Restricted user** do not see **Workflows**.

Read [Workflow access](/integrations/workflow-options-limits#workflow-access) for each permission.

## How Workflows work

A workflow is a graph made of three types of building blocks:

| Building block | What it does | Example |
| --- | --- | --- |
| **Trigger** | Starts the workflow when a matching event occurs. | A member earns loyalty points. |
| **Operator** | Currently, only **IF**. Chooses **True** or **False** from rules on the event. | Points earned are greater than 100. |
| **Webhook callout** | Sends the event to your endpoint. | Send the event to your CRM. |

Connect a trigger to one or more webhook callouts when every matching event should be sent. When an event matches the trigger, Voucherify starts a run and executes every callout on that direct path.

Put an operator (for example, **IF**) between the trigger and the callout when only some events should be sent. The run follows **True** when the rules match and **False** when they do not. Only the blocks connected to the taken path run. A path with no connection does not send a callout.

A missing field makes that rule false. The workflow does not fail because the field was absent. Read [IF operator](/integrations/workflow-options-limits#if-operator) for the rules, operators, and what a missing field does to the path.

One trigger can connect to several webhook callouts. Each **True** or **False** output connects to one next block. A webhook callout can accept connections from several triggers or operators.
