The `LEFT` event indicates that a member left a Loyalty v2 tier and does not qualify for any other tier in the tier structure.

<Note>
This page documents only the event data nested under `data`. See [Introduction to webhooks](/api-reference/introduction-to-webhooks) for the shared webhook structure, and [Workflows webhooks](/api-reference/workflows-webhooks) for the full Workflows webhook payload.
</Note>

This event can trigger a workflow when **Loyalty transaction** is configured with the **Tier transactions** group and the `LEFT` transaction type. If the workflow reaches a **Webhook callout** action, Voucherify sends a webhook to the action's target URL.

Workflows send this transaction in the `data.trigger` object. The example uses the `APPROVED` status. A workflow can filter the trigger by transaction status: `PENDING`, `APPROVED`, or `REJECTED`. The matched status is available in `data.trigger.transaction.status`; it does not create a separate event type.

Voucherify creates this transaction when a member who has a tier no longer qualifies for any tier. If a lower tier still applies, Voucherify creates a `DOWNGRADED` transaction instead. The `LEFT` transaction is created when:
- The member's point balance or points earned in the tracking period drop below the minimum of every tier. Depending on your tier structure configuration, the member may still qualify for a tier despite the point balance being below the minimum.
- The member's tier retention period ends, and the member does not qualify for any tier.
- The member no longer matches the segments required by a tier with segment qualification rules and does not qualify for any other tier.

`details.tier_to` is `null`. `details.tier_from` is the left tier ID. `transaction.tier_id` is `null`.
