The `UPGRADED` event indicates that a member moved to a higher Loyalty v2 tier.

<Note>
This page documents only the event data nested under `data`. See [Introduction to webhooks](/api-reference/introduction-to-webhooks) for the shared webhook structure, and [Workflows webhooks](/api-reference/workflows-webhooks) for the full Workflows webhook payload.
</Note>

This event can trigger a workflow when **Loyalty transaction** is configured with the **Tier transactions** group and the `UPGRADED` transaction type. If the workflow reaches a **Webhook callout** action, Voucherify sends a webhook to the action's target URL.

Workflows send this transaction in the `data.trigger` object. The example uses the `APPROVED` status. A workflow can filter the trigger by transaction status: `PENDING`, `APPROVED`, or `REJECTED`. The matched status is available in `data.trigger.transaction.status`; it does not create a separate event type.

Voucherify creates this transaction when the member already has a tier and the tier calculation assigns a higher one:
- The member's point balance or points earned in the tracking period reach a higher tier. The same result follows a segment change that makes a higher tier apply.
- A point-earned tier structure uses `NEXT_TRACKING_PERIOD`. The upgrade waits until the next tracking period. Until then, the recalculation is an `EVALUATION_REFRESHED` transaction. The `UPGRADED` transaction is created when that period starts.

Retention does not delay an upgrade. A point change that keeps the member in the same tier is an `EXPIRATION_CHANGED` or `EVALUATION_REFRESHED` transaction.

`details.tier_from` and `details.tier_to` are tier IDs. They are not nested tier objects.
