The `POINTS_RETURNED` event indicates that points spent on a reward were returned to a Loyalty v2 card.

<Note>This page documents only the event. If you need more details about the webhook payload data that includes this event, go to [Introduction to webhooks](/api-reference/introduction-to-webhooks "Introduction to webhooks v2024-01-01") page.</Note>

This event can trigger a workflow when **Loyalty transaction** is configured with the **Card transactions** group and the `POINTS_RETURNED` transaction type. If the workflow reaches a **Webhook callout** action, Voucherify sends a webhook to the action's target URL.

The example shows the content of `data` for a transaction with the `APPROVED` status. A workflow can filter the trigger by transaction status. The matched status is available in `data.transaction.status`; it does not create a separate event type.

Refunding a reward also creates a separate `REFUND` reward transaction. That payload is not included in this event. Use the [Refund event](/api-reference/loyalty-transactions/reward/refund) to get details about the reward transaction. When the original reward was loyalty card points, Voucherify also creates a separate `POINTS_PURCHASE_REVERSED` transaction on the destination card. A `POINTS_RETURNED` event can also occur without `POINTS_PURCHASE_REVERSED` when the original reward was not loyalty card points. Use the [Points purchase reversed event](/api-reference/loyalty-transactions/card/points-purchase-reversed) to get details about the destination card transaction.
