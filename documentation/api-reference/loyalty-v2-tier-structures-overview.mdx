A *tier structure* defines the tiering model for a loyalty program: the levels members can reach, and the rule that decides which level a member currently qualifies for. Tier structures are optional. A program can run entirely on points and rewards without any tiers.

## Tier structure types

A tier structure qualifies members based on exactly one of two measures, set through its `type`:
- `POINT_BALANCE`: The member's current point balance on the associated card.
- `POINT_EARNED`: The total points the member has earned over a given period, regardless of how many have since been spent or expired.

Only the configuration object matching the chosen type (`point_balance` or `point_earned`) can be set; the other must be left empty. If not specified, a tier structure defaults to no tier expiration (`NO_RETENTION`) and multi-level downgrade (`MULTI_LEVEL`).

## Tiers

Each tier structure contains its own nested tiers (like Bronze, Silver, and Gold). List them with the [list tiers](/api-reference/tier-structures/list-tiers) endpoint. Create, update, and remove tiers in one API request with [Batch create, update, and remove tiers](/api-reference/tier-structures/batch-create-update-and-remove-tiers). A tier structure can hold a maximum of 100 tiers.

Each tier can define its own downgrade behavior or inherit the parent structure's setting (`INHERIT`), which is the default when not specified. A tier can also set `points_expiration` to inherit the structure's rules or override how points are retained while the member is in that tier. You can set or change that override only while the tier structure is `DRAFT`.

While the tier structure is `DRAFT`, the batch can create, update, and remove tiers. In any other status (`ACTIVE`), create and remove are rejected, and an update can change only `name` and `metadata`.

## Lifecycle

A tier structure is created in `DRAFT` status by default. Use [Activate tier structure](/api-reference/tier-structures/activate-tier-structure) to move it to `ACTIVE`. Once a tier structure leaves `DRAFT`, only `name` and `metadata` can still be updated on the structure and on its tiers. The qualification logic itself stays fixed to protect members already progressing through the tiers.

[Delete tier structure](/api-reference/tier-structures/delete-tier-structure) sets `status` to `DELETED` and returns that tier structure. Deletion fails with `resource_in_use` when a program, earning rule, or reward still references it. To delete a tier structure, you must first unassign it from all referenced resources.

## Assigning a tier structure to a program

A program can have at most one tier structure assigned at a time, connected through the [program batch assignment endpoint](/api-reference/programs/batch-assignunassign-tier-structures). Unassigning a tier structure is only allowed while the program is in `DRAFT` status. Once the program is active, you can't unassign a tier structure. This prevents members from losing their tier context on a live program.
